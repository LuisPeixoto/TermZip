# Product

## Platform

web

## Stack
Static HTML, CSS and a little JavaScript, generated by a small Python script from one template and one translation file per language (delegated: it is the simplest thing GitHub Pages can serve, needs no framework, and keeps the page fast). Deployed to GitHub Pages at https://luispeixoto.github.io/TermZip/ with a base URL that can change if a custom domain is added.

## Users
Developers and power users who live in a terminal on macOS, Windows or Linux, and also people who are curious about the terminal and are deciding whether to try one. They judge a terminal in seconds, want to see the real application, install it with one command, and need to trust it (privacy, open source, signed updates).

## Product Purpose
TermZip is an open-source (MIT) desktop terminal written in Rust with a Tauri shell. It is a real terminal (the user's own shell, vim, tmux, SSH) that also turns every finished command into a block with its exit code, duration and output, ready to copy or run again. Version 1.0.0 is published.

## Positioning
A real terminal that turns each command into a copyable block, runs plugins in a WebAssembly sandbox with no imports, and sends nothing anywhere: no accounts, no telemetry, updates only when asked and signed.

## Operating Context
Installed with `brew install --cask luispeixoto/termzip/termzip` (macOS), `scoop bucket add termzip https://github.com/LuisPeixoto/scoop-termzip` then `scoop install termzip` (Windows), or from GitHub Releases (macOS dmg for Apple silicon and Intel, Windows exe and msi, Linux AppImage, deb and rpm). Winget manifests exist but are not submitted yet.

## Capabilities and Constraints
- Blocks for zsh, bash, fish and PowerShell; tabs and split panes with session restore; search and block filter; safe links; profiles including SSH and WSL; snippets with values that are typed and never run; project tasks (package.json, Cargo, Makefile, justfile, deno.json) in the command palette; git branch in the status bar; 12 built-in themes plus import from iTerm2, Windows Terminal, Ghostty, Kitty and Alacritty; every shortcut rebindable; plugins (WebAssembly, plugin API 1) with a signed catalog.
- Accessibility: screen reader setting, reduced motion, WCAG AA contrast in every theme.
- Privacy and security: no telemetry, network only when a person presses a button, signed updates, a written security review, twelve fuzz targets. No independent audit has been done.
- Known limits that must be stated honestly: builds are not signed with an Apple or Windows certificate yet (macOS and Windows warn on first launch; checksums are published); Windows and Linux have been checked by CI and smoke runs, not yet by long interactive use; flood output on Windows is slower.
- Performance on the reference Mac (Intel, release build): first prompt in about 0.6 s, about 200,000 lines per second of output, about 600 MB with the web view (see docs/performance.md).
- Plugin API 1 and the settings, layout and theme formats are promised stable through 1.x (docs/stability.md).

## Brand Commitments
Name "TermZip". The mark is `assets/icon.png` and `docs/images/termzip-mark.svg`. Interface identity so far: zinc neutrals with a blue accent, dark and light themes. Voice: plain, precise, no hype. The page is written in English and translated into Spanish, Portuguese and Chinese.

## Evidence on Hand
Real screenshots in `docs/images/` (Dracula with plugins, themes, command palette, snippets, tasks, SSH profile, plugin catalog, updates, screen reader). Measured numbers in `docs/performance.md`. The changelog and docs. There are no testimonials, customer logos, star counts, user numbers or comparisons with other terminals, and none may be invented.

## Product Principles
- Show the real application, not an illustration of it.
- Say what is not done yet as plainly as what is.
- Privacy is a fact to show (what is checked, what is sent: nothing), not a slogan.
- The first action is installing it; make that a single copyable command per system.
- Every claim on the page must be checkable in the repository.

## Accessibility & Inclusion
WCAG 2.1 AA at minimum for the page, keyboard use, visible focus, reduced motion respected, readable in dark and light, and correct language tags and typography for English, Spanish, Brazilian Portuguese and Chinese.
